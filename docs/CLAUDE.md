## 1. What the project is

A small 2D survival game called **Square Baby** (window title). The player is a square sprite that continuously shrinks. Collecting health items makes it grow, fire items make it shrink, and a wandering enemy ends the run on contact. Grow to **500 px** to win. Shrink below 3 px or touch the enemy (while under 500 px) to lose. Space restarts after either ending.

- Language: C++17
- Libraries: SDL2, SDL2_image (PNG textures), SDL2_ttf (score text), all installed through vcpkg manifest mode
- Platform: Visual Studio (MSVC) project for Windows x64. A CMake build exists for Linux/macOS but is untested on Windows.
- Size: gameplay is split across nine source files (`Player`, `Enemy`, `Health`, `Fire`, `Collision`, `GameLogic`, `Renderer`, `SDLHelpers`, `game.cpp`). `game.cpp` is just `main()`, under 50 lines.
- Repo state: README, MIT `LICENSE`, `.gitignore`, `CMakeLists.txt`, `vcpkg.json`, `NEXT_STEPS.md` present. Still no automated tests or CI.

## 4. Build and run

- Open `sdl.sln` in Visual Studio and pick **Debug | x64** or **Release | x64**. Both are verified to build from the vcpkg manifest alone and run correctly. The Win32 configurations still exist in the project file but are not wired up or tested; treat them as unsupported.
- Dependencies are declared in `vcpkg.json` and installed automatically on the first build (`VcpkgEnableManifest` is set in `sdl.vcxproj`). The first build of each configuration takes several minutes while vcpkg compiles the packages. `vcpkg integrate install` must have been run once on the machine.
- `vcpkg.json` contains a `builtin-baseline` commit hash. This is required: the vcpkg bundled with Visual Studio is not a git clone and refuses to resolve packages without one. Keep the hash in the repo, it is what makes the build reproducible.
- The vcpkg MSBuild integration links the libraries and copies the DLLs next to the exe automatically (`SDL2.dll`, `SDL2_image.dll`, `SDL2_ttf.dll`, `libpng16.dll`, `freetype.dll`, `z.dll`, `bz2.dll`, `brotlicommon.dll`, `brotlidec.dll`). A harmless `'pwsh.exe' is not recognized` message may appear in the build log on machines without PowerShell 7; the DLLs are still copied.
- `PlatformToolset` is `v145` in all four configurations. Confirmed installed and working on the dev machine.
- `Release|x64` uses `SubSystem` `Console`, same as the other configs, because the code uses a plain `main()` (`SDL_MAIN_HANDLED` is defined in `SDLHelpers.hpp`, so `SDL2main.lib` is not needed).
- The renderer uses `SDL_RENDERER_PRESENTVSYNC`, so frame pacing follows the display's refresh rate. There is no manual delay.
- Asset paths: `GameConstants.hpp` defines `ASSET_IMAGES_DIR "assets/images/"` and `ASSET_FONTS_DIR "assets/fonts/"` as `#define`s (they must stay macros, string-literal concatenation breaks with `constexpr const char*`). The working directory must be the project root, or wherever `assets/` sits, when running the exe directly. Running from Visual Studio uses the project folder, which works.
- CMake (`cmake -B build && cmake --build build`) copies `assets/` next to the executable and finds SDL via pkg-config. That is fine on Linux/macOS, but a plain Windows install has no pkg-config, so it fails at `find_package(PkgConfig REQUIRED)`. Visual Studio may try to auto-configure `CMakeLists.txt` when the folder is opened and show a failure; that is expected and harmless. `CMakeLists.txt` also still declares an unused `ASSET_DIR` variable.

## 5. Architecture

### 5.1 `SDLHelpers.hpp` / `SDLHelpers.cpp`

`GameContext` (window, renderer, `Events`, `score_font`) is passed by reference into every `SDL__*` function. The cached `score_font` is a `TTF_Font*` loaded once in `SDL__CreateWindow` and closed in `SDL__Destroy`. `GameContext::lastRun` no longer exists. `Events` is level-triggered (`exit, left, right, up, down, space, pause`).

| Function | Used by the game? | Notes |
|---|---|---|
| `SDL__CreateWindow(ctx, title, w, h)` | yes | Separate checked `SDL_Init`/`IMG_Init`/`TTF_Init`, accelerated + vsync'd renderer, loads the score font (30 px) once, clears to black. Returns 0 on success, 1 on failure. Failure paths call the matching `*_Quit` functions. |
| `SDL__Events(ctx)` | yes | Arrows, Space, P, window close. |
| `SDL__DrawText(ctx, text, x, y, size, "#RRGGBB")` | yes | Uses the cached `ctx.score_font`. **The `size` parameter is ignored**, the font is fixed at 30 px (the only size the game draws). Checks the surface and texture results, no per-call font open/close (B22). |
| `SDL__Destroy(ctx)` | yes | Closes the font, destroys renderer/window, then `TTF_Quit`, `IMG_Quit`, `SDL_Quit` (B23). |
| `SDL__SetColor(ctx, "#RRGGBB")` | indirectly | Validates length 7, the leading `#`, and six hex digits, returns black and logs on bad input (B24). Still sets the renderer draw color as a side effect. |
| `SDL__Clear(ctx, color)` | no | The only remaining dead helper. Safe to delete. |

Deleted in Session 2 (dead code with known bugs): `SDL__DrawPoint`, `DrawLine`, `DrawRect`, `FillRect`, `DrawCircle`, `FillCircle`, `DrawImage`. Deleted afterwards: `SDL__Present` (the old manual frame limiter, replaced by vsync).

### 5.2 `Player.hpp` / `.cpp`

`PlayerState { size, x, y, small_tex, big_tex, current_tex }`. `current_tex` is an alias into `small_tex`/`big_tex`, never an owner (B1). `Player_UpdateSprite` picks the sprite for the current frame before drawing (B11). `Player_Shrink` is the log-based decay `size -= 8.3 * ln(size) * 0.3 * dt/1000`. `Player_HandleMovement` builds a direction vector from the held keys and **normalizes it** before scaling by `PLAYER_SPEED` and `deltatime`, so diagonal and axis-aligned movement are both 180 px/s (B19). Opposite keys cancel exactly. `Player_ClampToWindow` clamps after movement (B8).

### 5.3 `Enemy.hpp` / `.cpp`

`EnemyState { x, y, direction, direction_timer, texture }`. `Enemy_Update`:

- `DirectionIsOpen()` checks wall bounds and item collision for a given direction in one call.
- `EnemyBlockedAt()`/`EnemyTryMove()` treat the health item as solid with a soft `ENEMY_HEALTH_AVOID_MARGIN` buffer, falling back to the item's real footprint only if the margin alone would block every direction. Fire is solid with no margin.
- `PickOpenDirection()` only re-evaluates when the direction timer elapses or the current direction is actually blocked (B18, merged as PR #25 on 2026-10-29). This is what fixed the old B9.
- If every direction is blocked (true deadlock) the enemy stands still, sets `direction = 0`, and retries every frame. It stays frozen until whatever blocks it goes away. Normally that is a health item or fire expiring. B25 fixes the bug where fire was revealed on top of the enemy, which made this deadlock reachable.
- Enemy movement is gated to `GameState::Playing` in `Game_RunFrame`, so it freezes during Game Over/Victory.

### 5.4 `Health.hpp`/`.cpp` and `Fire.hpp`/`.cpp`

`HealthState { x, y, size, texture }`, `FireState { x, y, size, visible, texture }`. Both use default member initializers (`size = -1`).

- `Health_SpawnIfNeeded` runs every frame, does nothing while `size > 0`, otherwise asks `FindSpawnPosition()` for a spot that avoids the player, enemy and visible fire. It tries at most `SPAWN_MAX_ATTEMPTS` (100) positions. On failure `size` stays at -1 and it retries next frame (B12).
- Fire is **not** pre-spawned. Hidden fire is simply `size = -1, visible = false`, and its `x`/`y` mean nothing. `Fire_Reveal` is called from `GameLogic.cpp` at the moment fire should appear. It picks a position with `FindSpawnPosition()` against the player, enemy and health item as they are right now, then sets `size = 50` and `visible = true`. It returns false if nothing valid was found (B25).
- `Fire_Shrink` shrinks visible fire by 10 px/s and hides it at size 0. It is not gated by `GameState::Playing`, so fire keeps shrinking during Game Over/Victory while health does not. This asymmetry is from the original and is unfixed.
- Health still uses `size <= 0` as its "needs respawn" signal while fire uses a real `visible` flag. Minor inconsistency, low priority.

### 5.5 `Collision.hpp`/`.cpp`

`Overlaps(a, b)` is the shared rect-overlap test (B6); touching edges do not count as overlap. `CollidedWithHealth/Fire/Enemy` build the player's rect against each item's current rect. The enemy rect is a real 50x50 everywhere.

`FindSpawnPosition(window_size, item_size, max_attempts, isBlocked, out_x, out_y)` is the shared bounded random placement helper: it tries up to `max_attempts` random positions, calls `isBlocked(rect)` (a `std::function`, usually a lambda) on each, and returns true with the first free one. On failure it returns false and leaves `out_x`/`out_y` untouched. It uses `rand()` (seeded in `SDL__CreateWindow`). Used by `Health.cpp` and `Fire.cpp`.

### 5.6 `GameLogic.hpp`/`.cpp`

`GameState { Playing, GameOver, Victory }` (B10). `GameWorld` bundles `PlayerState`, `EnemyState`, `HealthState`, `FireState`, `state`, `score_time`, `health_counter`, `window_size`, and the three non-player textures (`background_tex`, `gameover_tex`, `win_tex`).

- `Game_LoadTextures` loads all nine textures. It is called **once, from `game.cpp` at startup**, no longer on restart.
- `Game_Reset(ctx, world)` resets round state only (state, player size/position/sprite, health and fire back to hidden, enemy position/direction/timer, score, `health_counter`). It does not touch textures (B21). The `ctx` parameter is unused now and kept only for the call site.
- `Game_RunFrame` runs update + collision each frame: player shrink (if `Playing`), sprite pick, enemy update (if `Playing`), health spawn and shrink, `Fire_Shrink` (not gated), player movement (if `Playing`), the three collision checks, score accumulation, the size<3 and size>=500 win/lose checks, and the restart-on-space check. Update, collide and the restart decision all happen before `Render_Draw`, so the first frame after a reset renders correctly (B11).
- Fire is revealed in the health collision block: each health item eaten while fire is hidden increments `health_counter`; at 3, `Fire_Reveal` is called. If it succeeds the counter resets to 0. If it fails (no free spot) the counter stays at 3 and the next health pickup retries.

### 5.7 `Renderer.hpp`/`.cpp`

`Render_Draw(ctx, world)` is the only place that calls `SDL_RenderCopy`. State-gated: player/enemy/health/fire/score draw only in `Playing`, the Game Over and Win overlays draw only in their states. A null texture makes `SDL_RenderCopy` fail silently and draw nothing, which is why a texture that failed to load shows up as an invisible object (see B26).

### 5.8 `game.cpp`

Just `main()`: create window, load textures, set the initial player position inline, then a loop of events -> compute `deltatime` -> `Game_RunFrame` -> `Render_Draw` -> `SDL_RenderPresent`. No gameplay logic.

## 6. Game rules and constants

| Thing | Value |
|---|---|
| Window | 700x700 |
| Player start | size 50, centered |
| Player speed | `PLAYER_SPEED = 180.0` px/sec, time based, normalized diagonally (B19) |
| Player shrink | `size -= 8.3 * ln(size) * 0.3 * dt/1000` per frame (time based) |
| Sprite swap | `size > 100` uses `Hestler.png` (big), else `BacheGherti.png` (small) |
| **Win** | `size >= window_size - 200` = **500** |
| **Lose** | `size < 3`, or touching the enemy while `size < window_size - 200` (500) |
| Immunity guards | health growth, fire penalty, and enemy-collision-ends-game are all gated on `player.size < window_size - 200` |
| Enemy | 50x50, starts at (100, 100), `ENEMY_SPEED = 60.0` px/sec, picks a new direction only when blocked or `ENEMY_DIRECTION_INTERVAL = 70/60` sec elapses (B18) |
| Health item | 50 px at spawn, shrinks 10 px/s, respawns via `Health_SpawnIfNeeded` (bounded, B12) |
| Health growth | flat `HEALTH_GROWTH = 40.0` px per item (B2) |
| Fire item | revealed after every 3 health items eaten, 50 px, shrinks 10 px/s, position chosen at reveal time (B25) |
| Fire penalty | flat `FIRE_PENALTY = 40.0` px per item (B2) |
| Spawn size | `ITEM_SPAWN_SIZE = 50`, spawn attempt cap `SPAWN_MAX_ATTEMPTS = 100` (static constant in `Health.cpp` and `Fire.cpp`) |
| Score | `score_time`, a `double` accumulated via `deltatime` while `Playing` (B13), displayed as `(int)score_time` |
| Controls | Arrow keys move, Space restarts, closing the window quits. `P` is read but unused (no pause feature). |

## 7. Frame loop, as it actually runs today

1. `SDL__Events(ctx)`, break on exit.
2. Compute `deltatime` from `SDL_GetTicks()`.
3. `Game_RunFrame(ctx, world, event, deltatime)`:
   - Shrink player (if `Playing`).
   - `Player_UpdateSprite`.
   - `Enemy_Update` (if `Playing`).
   - `Health_SpawnIfNeeded`, then `Health_Shrink` (if `Playing`).
   - `Fire_Shrink` (not gated by `Playing`).
   - `Player_HandleMovement` (if `Playing`), which clamps internally.
   - Collision checks: health (grow + maybe `Fire_Reveal`), fire (shrink + hide), enemy (-> `GameOver`).
   - Score accumulation (if `Playing`).
   - Size<3 -> `GameOver`; size>=500 -> `Victory`.
   - If ended and Space pressed: `Game_Reset` (state only).
4. `Render_Draw(ctx, world)`: all drawing, fully state-gated.
5. `SDL_RenderPresent(ctx.renderer)`: vsync paces this.

## 8. Known bugs

Severity: **High** crash or undefined behavior or broken core loop, **Medium** wrong behavior, **Low** cosmetic or latent.

### Fixed

B1 (double texture destroy), B2 (log-formula div-by-zero/absurd growth), B3 (incomplete restart), B4 (unchecked init/load failures), B5 (wrong SDL_image init), B6 (spawn overlap checks), B7 (frame-rate-dependent speed/timing), B8 (player could leave the window), B9 (enemy stuck at walls / moving during Game Over), B10 (two booleans instead of a `GameState` enum), B11 (rendering and logic interleaved), B13 (frame-count-based score), B15 (uninitialized variables), B18 (enemy picks from genuinely open directions, PR #25).

Fixed in Sessions 1-3:

**B12. Spawn loop can in theory never end.** `Health_SpawnIfNeeded` and the fire placement now use `FindSpawnPosition()` (Collision.hpp/.cpp) with a 100-attempt cap. On failure the item stays unspawned and retries next frame.

**B19. Diagonal movement not normalized.** `Player_HandleMovement` normalizes the direction vector, diagonal speed now equals axis speed.

**B20. Fire re-rolled its candidate position every frame while hidden.** First fixed by guarding `Fire_SpawnIfNeeded` on `size > 0` (pick once, hold). **Superseded by B25**, which removed the pre-picked position altogether.

**B21. `Game_Reset` reloaded every texture on every restart.** Now resets round state only; textures load once at startup.

**B22. `SDL__DrawText` opened and closed the font every frame, and leaked it on a failure path.** The font is cached in `GameContext::score_font`, loaded once in `SDL__CreateWindow` and closed in `SDL__Destroy`.

**B23. `IMG_Quit()` was never called.** Added to `SDL__Destroy`.

**B24. `SDL__SetColor` only checked `strlen == 7`.** Now also checks the leading `#` and six hex digits.

**B25. Fire placed in advance went stale (regression introduced by B20's first fix).** B20 held a position picked while the fire was hidden, so by the time it was revealed the enemy could be standing on it, and the enemy then deadlocked until the fire expired. `Fire_SpawnIfNeeded` was removed; `Fire_Reveal` picks and validates the position at the moment the fire becomes visible.

**B26. `Enemy.png` was a JPEG with a `.png` extension.** The old vendored SDL_image build had a JPEG decoder and loaded it anyway; vcpkg's default build does not, so the load failed with `Unsupported image format` and the enemy was invisible (but still collided, since collision does not use the texture). Re-exported as a real PNG. Lesson: a missing sprite means a failed texture load, check the console for `Failed to load texture`.

Other cleanups done in the same sessions: dead drawing helpers deleted (see 5.1), `SDL__Present` and `GameContext::lastRun` deleted, `srand(time(NULL))` cast to `unsigned int` to clear warning C4244, stale `SDL.h` entry removed from `sdl.vcxproj`, the `sdl/` leftovers folder deleted.

### Still open

**B14. Narrowing conversions.** Largely addressed with explicit `(int)` casts in every `SDL_Rect` construction. The underlying `double`-position / `int`-rect mismatch is inherent to the design.

**B27. `IMG_Init` result is not checked per format.** `SDL__CreateWindow` requests `IMG_INIT_PNG | IMG_INIT_JPG` and only checks that the result is nonzero, so it passed even though this vcpkg build has no JPEG support. The game only uses PNG. Fix: request `IMG_INIT_PNG` only and check `(IMG_Init(wanted) & wanted) == wanted`.

Other items from the code review, not yet numbered or scheduled:

- `LoadTextureChecked` logs a failure but lets the game start with a null texture, which later shows up as an invisible sprite (this is how B26 hid). Required textures should stop initialization.
- A very long frame (window drag, debugger pause) produces a large `deltatime` and a large movement step. Clamping `deltatime` would fix it.
- `Fire_Shrink` is not gated by `GameState::Playing` while `Health_Shrink` is.
- `HealthState` uses `size <= 0` as its inactive signal instead of an explicit flag.
- `SDL__Clear` is dead code. `SDL__SetColor` mutates the renderer draw color as a hidden side effect.
- `SDL__DrawText`'s `size` parameter is ignored, which is misleading for any future caller.
- The `Win32` configurations in `sdl.vcxproj` are unwired and untested.
- `CMakeLists.txt` declares an unused `ASSET_DIR` variable and fails on plain Windows.

## 13. Working rules for future sessions

- Keep SDL2 and C++. Do not switch libraries or add an engine.
- Smallest change that fixes the problem, one logical fix per commit, message says which bug ID from this file it addresses. Branch names are narrow and scoped to the actual work (e.g. `session3-vcpkg-manifest`).
- When a bug is fixed, update section 8 here in the same session as the code change, not after. This file previously drifted out of sync for several steps' worth of work.
- Compile and run after every change, including a full win/lose/restart playtest. If it can't be run, say so instead of claiming it works.
- A change that moves state earlier or caches a value (B20) can silently make it stale (B25). When holding a value across frames, check what else moves in the meantime.
- If a sprite is invisible, check the console for `Failed to load texture` first. Verify an asset's real format matches its extension.
- Do not touch the vendored-binary or vcpkg setup without confirming both Debug|x64 and Release|x64 build afterwards. Always keep the `builtin-baseline` in `vcpkg.json`.
- Keep the owner's style where reasonable unless that's part of what's being refactored.
